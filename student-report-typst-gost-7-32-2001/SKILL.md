# Студенческие отчёты: Typst, PDF и DOCX

Готовь отчёты на русском по заданию и материалам пользователя. Typst — единый источник текста, таблиц, формул и ссылок для PDF и Word. Не придумывай измерения, команды, успешные запуски, скриншоты, результаты испытаний, литературу или личные данные.

## Начало работы: структура и выбор титула

**Первое действие при создании нового отчёта — создать модульную структуру**, до написания глав. Пути к скриптам ниже заданы относительно директории этого навыка; при работе в другом каталоге используй абсолютные пути.

```bash
python3 scripts/init_project.py /path/to/report-project
```

Скрипт создаёт корневой `report.typ` и шесть поддиректорий: `images/`, `tables/`, `titles/`, `settings/`, `chapters/`, `bibliography/`. Существующий непустой проект не перезаписывается. При редактировании готовой работы сначала прочитай её структуру и сохраняй пользовательское содержание.

**Для нового отчёта спроси, какой титульник использовать**, если пользователь ещё не выбрал его в текущей задаче. Это требование пользователя, добавленное вместе с его образцом курсовой:

- `lab` — компактный титул лабораторной/практической, несколько исполнителей;
- `mai-course` — титул МАИ из пользовательской курсовой: вуз выделен, интервалы 5 и 3 см, вариант, группа рядом с фамилией, должность проверяющего;
- `generic` — нейтральный титул для другого вуза с настраиваемыми реквизитами.

При необходимости добавь предложенный пользователем титул отдельным модулем; для DOCX также реализуй соответствующую ветку экспортёра. Подробности и критерии выбора: [references/title-pages.md](references/title-pages.md).

Вопрос о титуле — выбор оформления, а не разрешение выполнять работу. Пока ожидаешь ответ, разбирай задание, изображения и содержание. Не подменяй отсутствие ответа выбором титула: `titles/selected.typ` остаётся `pending`, сборка сообщает о необходимости выбора. Уже выбранный титул не переспрашивай. Если выбор известен заранее:

```bash
python3 scripts/init_project.py /path/to/report-project --title mai-course --profile student-course
```

По умолчанию выдавай проект и PDF. При запросе Word добавь DOCX; для запроса «только DOCX» выдай DOCX и сохрани исходный проект. Если формат неясен и влияет на работу, спроси его вместе с титулом.

## Материалы и профиль

Из задания извлеки тип работы, дисциплину, тему, вариант, цель, обязательные шаги, результаты, состав исполнителей, группу, проверяющего, город/год, лимит страниц и исключения. Недостающие существенные сведения уточняй; неизвестное оставляй незаполненным в черновике, а не выдумывай. Личные данные и тема из образца курсовой не становятся значениями по умолчанию.

Фотографии и скриншоты изучай средствами понимания изображений. Терминальные скриншоты вставляй как изображения, если пользователь не просил текстовые листинги. Сохраняй и положительные, и отрицательные наблюдавшиеся результаты.

Выбирай профиль отдельно от титула:

| Профиль | Назначение |
| --- | --- |
| `student-lab` | Короткий отчёт; полужирные заголовки; справа 10 мм; короткие `рис. N` / `табл. N`; сквозные формулы; без содержания по умолчанию |
| `student-course` | Оформление по пользовательскому образцу; справа 15 мм; полужирные заголовки; главы по центру прописными; содержание; формулы `(1.1)` по главам |
| `gost-2001-strict` | Правила редакции 2001 года; полные ссылки на рисунки/таблицы; обычное начертание заголовков; без заявления о полной нормативной проверке одним скриптом |

Общие настройки: A4, Times New Roman 14 пт, чёрный текст, основной текст по ширине, первая строка 1,25 см, межстрочный 1,5, слева 30 мм и сверху/снизу 20 мм. Титул учитывается в нумерации, его номер скрыт, остальные номера снизу по центру. Год фиксируется при создании проекта и уточняется по заданию.

Читай [references/student-profile.md](references/student-profile.md) для местных правил и [references/gost-7.32-2001.md](references/gost-7.32-2001.md) при нормативных вопросах/строгом профиле. Не выдавай TNR 14, отступ 1,25 см, сокращённые ссылки или полужирные заголовки за требования ГОСТ 7.32-2001. Явные указания пользователя/преподавателя имеют приоритет; отмечай значимые отклонения. Не заменяй редакцию 2001 на 2017 без запроса.

## Написание модульного отчёта

Читай [references/project-format.md](references/project-format.md) перед заполнением проекта: там API блоков и рабочие примеры. Модули глав экспортируют массивы блоков с обычным Typst-содержимым: `para[...]`, `section(...)`, `screenshot(...)`, `result-table(...)`, `formula(...)`. Основной файл соединяет эти массивы и вызывает `render-report(...)`. Не пиши видимое содержание снаружи этой модели, если нужен DOCX: экспортёр читает именно модель.

- Реквизиты — `settings/metadata.typ`, оформление — `settings/config.typ`, выбор титула — `titles/selected.typ`.
- Изображения — `images/`, определения таблиц — `tables/`, главы — `chapters/`, реальные использованные источники — `bibliography/sources.typ`.
- Изображения и литература не генерируются для заполнения пустот. Стартовый проект содержит только каркас.
- Для короткой лабораторной обычно достаточно цели, краткой необходимой теории, хода работы, результатов и вывода. Таблица результатов нужна, когда есть соответствующие данные.
- Для курсовой используй введение, содержательные главы/подразделы, заключение и реально использованные источники. Не добавляй содержания, приложений или библиографии вопреки исключениям пользователя. Для работы до 10 страниц содержание по ГОСТ 2001 можно опустить.

### Абзацы, интервалы и переносы

Для местных профилей основной текст: TNR 14 пт, по ширине, первая строка 1,25 см, межстрочный интервал 1,5. Дополнительные интервалы до и после обычного абзаца — **0 пт**: расстояние между последней строкой одного абзаца и первой следующего должно совпадать с шагом строк внутри абзаца. Не сжимай границу абзацев и не вставляй пустые строки. Интервалы заголовков и подписей задаются отдельно.

**Автоматические переносы слов отключены во всём документе**, включая основной текст, заголовки, подписи и таблицы. Не добавляй мягкие переносы U+00AD и ручные дефисы ради заполнения строки; смысловые дефисы в словах сохраняются. Чтобы составные термины вроде «VPN‑доступ», «веб‑интерфейс» и «IP‑адрес» оставались целиком на строке, используй неразрывный дефис U+2011. Явное требование пользователя/преподавателя может изменить эти настройки.

В `config.typ`: `line-spacing: 1.5`, `paragraph-spacing: 0` (добавка в пт к обычному шагу), `hyphenate: false`. В Typst используй `top-edge: 0.8em`, **`bottom-edge: -0.2em`**, `leading: 0.5em`, **`par.spacing: 0.5em`** при нулевой добавке: для 14 пт шаг равен 21 пт и внутри, и между абзацами. `spacing: 0pt` в Typst не равнозначен Word «до/после 0 пт» и сжимает межабзацный шаг. Если абзац обёрнут в `block`, сохраняй этот промежуток перед блоком; не обнуляй его ради удержания с рисунком. В DOCX: межстрочный множитель 1,5, `before=0`, `after=0`, отключённый `autoHyphenation` и `suppressAutoHyphens` в стилях.

Проверяй участок с двумя соседними многострочными абзацами, в том числе перед рисунком. В PDF сравни шаг строк внутри и на границе абзацев; в Word проверь стиль Normal и отрисовку. Заголовки не заменяют эту проверку. Детали геометрии: [references/project-format.md](references/project-format.md#геометрия-и-шрифты).

### Заголовки всех уровней

Оформляй заголовки через `section(...)` и `structural(...)`, а не как `para[1. Цель работы]` и не как просто выделенный абзац. Они должны сохранять семантику заголовка, попадать в навигацию и визуально отделяться от основного текста. В DOCX используй стили `Heading 1`, `Heading 2`, `Heading 3`; запрет прямого начертания в отдельных runs не должен отменять полужирный стиль.

Для местного профиля `student-lab` используй TNR 14 пт и следующие правила:

| Тип | Оформление | Интервал до / после |
| --- | --- | --- |
| Раздел: `1. Цель работы` | `section(...)`, уровень 1; полужирный, слева, с прописной буквы | 12 / 6 пт |
| Подраздел: `3.1. Установка` | `section(..., level: 2)`; полужирный, слева, с прописной буквы | 9 / 6 пт |
| Именованный пункт: `3.1.1. Проверка` | `section(..., level: 3)`; полужирный, слева, с прописной буквы | 6 / 3 пт |
| Ненумерованный заголовок раздела | `section(..., numbered: false)`; оформление своего уровня, без номера | По уровню |
| Структурный заголовок: `ВВЕДЕНИЕ`, `ЗАКЛЮЧЕНИЕ`, список источников, название приложения | `structural(...)`; полужирный, по центру, прописными, без номера раздела | 12 / 6 пт |
| `СОДЕРЖАНИЕ` | Как структурный заголовок, но не включать его в собственное оглавление; в DOCX отдельный стиль `TOC Heading` | 12 / 6 пт |

Номер каждого нумерованного заголовка всегда заканчивается точкой: `1. Цель работы`, `2.3. Настройка`, `3.1.1. Проверка`. Это относится и к содержанию. Точка задаётся общей нумерацией, а не вручную в тексте; в конце самого названия точка не ставится. У заголовков нет абзацного отступа, подчёркивания, переноса слова по слогам и выравнивания по ширине. Сохраняй интервал 1,5 внутри многострочного заголовка, не разрывай его между страницами и удерживай вместе с последующим текстом. Отступы задавай свойствами блока/стиля, а не пустыми строками. Правила разрывов зависят от вида работы и применяются в общей модели до экспорта:


| Элемент | Лабораторная (`student-lab`) | Курсовая (`student-course`) |
| --- | --- | --- |
| Обычный раздел первого уровня: `1.`, `2.`, `3.` | Продолжается на текущей странице; принудительного разрыва нет | Каждый раздел начинается с новой страницы |
| Подразделы и пункты: `1.1.`, `2.3.`, `3.1.2.` | Продолжаются на текущей странице | Продолжаются на текущей странице |
| Введение, вывод/заключение, содержание, список источников, приложение | Начинаются с новой страницы | Начинаются с новой страницы |

Структурный раздел занимает отдельную страницу или несколько страниц: следующий раздел первого уровня тоже начинается с новой страницы. Содержание завершается разрывом страницы. Естественный переход при нехватке места допустим; заголовок удерживается с последующим текстом. Не вставляй разрывы между обычными лабораторными пунктами `3.`, `3.1.`, `3.2.`, `4.`. «Цель работы», «Ход работы», «Результаты работы» оформляй через `section(...)`; не подменяй их `structural(...)` ради вида заголовка.

В API `new-page: none` означает правило профиля; `prepare()` определяет итоговый флаг для PDF и Word. Явные `true`/`false` нужны только для согласованного исключения. Например, уже нумерованный «7. Вывод» можно сохранить с `new-page: true`. При смене профиля удаляй устаревшие ручные флаги, которые противоречат новому правилу. В Typst применяй слабый разрыв, в DOCX — `page_break_before`, чтобы не появлялись пустые страницы.

Точка после номера (`heading-number-suffix: "."`) и правила непрерывных пунктов лабораторной — пользовательский формат, а не требования ГОСТ 7.32-2001. Нормативная справка описывает стандарт отдельно; не отменяй явный пользовательский формат ссылкой на неё и не заявляй полное строгое соответствие при таком отклонении.

В `student-course` те же полужирные стили и интервалы, но разделы уровня 1 — по центру прописными; уровни 2–3 — слева. В `gost-2001-strict` сохраняй обычное начертание; явные пользовательские исключения, включая точку после номера, имеют приоритет над нормативной справкой и отмечаются как местные правила. Явные требования пользователя имеют приоритет. Подписи рисунков/таблиц оформляй как подписи, а реквизиты титула — в модуле титула; они не являются разделами документа.

При правке оформления синхронно обновляй `settings/config.typ`, Typst-рендерер и стили экспортёра DOCX. В Typst предпочитай `show heading: set ...` и настройки `block` по уровню: обёртка `align` вокруг готового заголовка может поглотить интервалы или нарушить удержание с текстом. Проверяй визуально каждый используемый уровень, стили/уровни структуры Word и отсутствие заголовков, оставшихся последней строкой страницы.

### Рисунки, таблицы, формулы и ссылки

Один рисунок на строку, по центру, подпись снизу `Рисунок N – ...`. Подпись таблицы сверху слева `Таблица N – ...`, без абзацного отступа. Таблицы с чёрной сеткой и без заливки. Вводи каждый рисунок/таблицу короткой фразой **до** объекта: `para[Результат приведён на @fig-check.]`. Ссылки по идентификаторам автоматически получают номер; не набирай номера вручную.

Для обычных скриншотов ориентируйся на высоту не более трети страницы вместе с подписью: в шаблоне `figure-max-height: 80` мм ограничивает само изображение, а `width` — максимальную ширину. Масштабируй пропорционально. Для подробной схемы или при потере читаемости задай обоснованное исключение `max-height` у конкретного рисунка; не уменьшай текст до неразборчивого размера ради числа.

Если вокруг полезного окна большие пустые поля или пользователь просит обрезку кодом, применяй `screenshot(..., crop: crop-px((x, y, w, h), source: (W, H)))`. Это обрезка при вёрстке, исходный PNG/JPEG остаётся неизменным. В PDF работает `report-image` из `settings/image-layout.typ`, в DOCX — штатная обрезка DrawingML с полным исходником внутри документа. Сначала осмотри изображение; не отсекай важные параметры, вывод, ошибки или контекст. Подробности макроса, единиц, ограничений и проверки: [references/image-layout.md](references/image-layout.md).

Формулы задавай нативной математикой Typst; номера справа в круглых скобках, ссылки `@eq-id` тоже в скобках. При нумерации по главам счётчик сбрасывается только с новой главой первого уровня. Поясняй обозначения сразу после формулы. Обычный TNR не содержит полной математической таблицы OpenType: отдельный математический шрифт указан в настройках и должен быть доступен. См. ограничения DOCX для сложных формул ниже.

### Лимит страниц

Сначала сокращай повторения и теорию, затем процедурный текст до 1–2 предложений на скриншот и лишние вертикальные интервалы. Не уменьшай обязательный кегль, не располагай скриншоты рядом и не обрезай полезный вывод. При невозможном сочетании требований сообщи о конфликте. Лимит относится к каждому запрошенному конечному формату, если пользователь не уточнил иначе.

## Сборка и проверка

Проверь `typst --version`, `typst fonts` и доступность выбранных шрифтов. Один лишь успешный `fc-match` не доказывает наличие TNR: он может вернуть замену. Шаблоны проверены с Typst 0.14.2. Если Typst или нужный шрифт недоступен, сохрани исходники и укажи, что сборка не выполнена; не подменяй формат или шрифт молча.

Из корня созданного проекта:

```bash
typst compile report.typ report.pdf
```

Для DOCX читай [references/docx.md](references/docx.md), затем запускай:

```bash
python3 /path/to/skill/scripts/export_docx.py report.typ report.docx
```

Экспортёр использует `typst query`, поэтому читает вычисленные `.typ`-модули и те же изображения. Это поддерживаемый формат проекта, а не универсальная конвертация любого Typst/PDF. Старые отчёты сначала перенеси в блоки без изменения содержания. Неподдерживаемые конструкции вызывают ошибку до замены выходного файла; расширь обработчик или явно обсуди необходимое представление, не выбрасывай содержание.

Проверка, с лимитом только когда он задан:

```bash
python3 /path/to/skill/scripts/preflight.py report.typ report.pdf --max-pages 5
# DOCX без ограничения страниц:
python3 /path/to/skill/scripts/preflight.py report.typ report.pdf --docx report.docx
# При лимите для Word дополнительно нужен PDF, отрендеренный из DOCX:
python3 /path/to/skill/scripts/preflight.py report.typ report.pdf --docx report.docx --docx-pdf word-render/report.pdf --max-pages 5
```

Проверка учитывает импортированные главы, ссылки до объектов, поля титула, порядок источников, число страниц и структуру DOCX. Она не доказывает визуальную корректность или полное соответствие ГОСТ. Отрендери PDF через `pdftoppm` либо `typst compile report.typ 'page-{p}.png'` и осмотри каждую страницу: титул ровно на одной странице, шрифты/отступы, отсутствие обрезаний, читаемость изображений, расположение подписей. DOCX отдельно открой/отрендери в Word или LibreOffice, обнови поля и содержание, проверь переносы и число страниц. Не объявляй непроверенную вёрстку проверенной.

## Выдача

Верни ссылки на PDF/DOCX согласно запросу и **весь модульный проект** (папку или ZIP), а не только `report.typ`, который без модулей не соберётся. Не включай проверочные синтетические результаты в пользовательский отчёт.
