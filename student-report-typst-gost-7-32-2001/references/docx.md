# Редактируемый Word из Typst

Экспортёр читает `<report-data>` через `typst query`: Typst сам вычисляет импорты, массивы глав, таблицы, формулы и ссылки. Результат не извлекается из PDF и не разбирается регулярными выражениями. Промежуточный JSON не нужно вести вручную. Текст остаётся абзацами Word, таблицы — таблицами, поддерживаемые формулы — Office Math (OMML), изображения встраиваются в DOCX.

## Запуск

Нужны Typst (проверено с 0.14.2), Python 3.10+ и `python-docx` 1.2.x. Установка в окружение проекта или временное окружение:

```bash
python3 -m venv /tmp/report-docx-venv
/tmp/report-docx-venv/bin/python -m pip install -r /path/to/skill/scripts/requirements-docx.txt
/tmp/report-docx-venv/bin/python /path/to/skill/scripts/export_docx.py /path/to/project/report.typ /path/to/project/report.docx
```

Зависимости нужны только для DOCX; создание Typst-проекта и проверка модели используют стандартную библиотеку Python. Скрипт не устанавливает пакеты, не отправляет файлы в онлайн-конвертеры и не меняет исходники. Выходной DOCX заменяется только после успешного формирования нового файла.

## Что переносится

- Три варианта титула и реквизиты; A4, поля, TNR, кегль, интервал, отступ, скрытый номер первой страницы и поле PAGE в колонтитуле.
- Обычные абзацы с интервалами до/после 0 пт и межстрочным множителем 1,5 по умолчанию; автоматические переносы выключены (`autoHyphenation=false`, `suppressAutoHyphens=true`).
- Заголовки уровней 1–3, жирный/курсив, перенос строки, короткий inline-code, подчёркивание, зачёркивание, верхний/нижний текстовый индекс и внешние ссылки.
- Внутренние `@id`: вычисленные номера, гиперссылки и закладки; полные подписи рисунков/таблиц.
- Рисунки PNG/JPEG по одному на строку с сохранением пропорций видимой области, пределом высоты и обратимой обрезкой DrawingML (исходное изображение встраивается целиком); таблицы без заливки с чёрными границами, заданными весами столбцов и повторяющимся заголовком.
- Настоящие маркированные/нумерованные списки Word, нумерация источников и разрывы страниц. Номера заголовков включают завершающую точку. `page_break_before` берётся из вычисленной модели: лабораторные пункты продолжаются, в курсовой новая глава уровня 1 начинается с новой страницы; структурные разделы отделяются в обоих профилях.
- Inline/block-формулы: текст/символы, дроби, верхние и нижние индексы справа, корни, простые матрицы/векторы. Нумерация формул совпадает с Typst.
- Содержание как поле TOC; обновление и окончательные номера страниц выполняются офисным приложением.

## Границы поддержки

Это экспорт **формата проекта этого навыка**. Произвольный старый `.typ` сначала адаптируй к `para`, `section`, `formula` и другим блокам, сохранив данные и смысл. Корневой файл служит сборщиком: содержимое, написанное за пределами модели, в Word не попадёт.

Не поддерживаются произвольные `show`/`set` внутри содержимого, контекстные функции, вложенные блоки в абзаце, сложные математические операторы/выравнивания, MiTeX как чёрный ящик, объединения ячеек, сноски и произвольные фигуры/графика. Неподдерживаемый узел вызывает ошибку с его названием. Не обходи ошибку удалением узла или превращением всей страницы в картинку. Расширь обработчик и проверь результат; если требуется иной компромисс, уточни его у пользователя.

Поддерживаемые математические структуры экспортируются в OMML без дублирования формулы строкой LaTeX. Для SVG/PDF/прочих изображений подготовь явный PNG/JPEG, сохрани оригинал, проверь разрешение. Не уменьшай читаемость ради успешного экспорта.

TNR и математический шрифт не встраиваются в Word-файл: для идентичного отображения они должны быть доступны на компьютере получателя. При контрольной отрисовке LibreOffice использовал собственные шрифты для OMML, несмотря на указанный Cambria Math; вёрстку формул в Word и LibreOffice проверяй отдельно. Обновление DOCX выполняется повторным запуском экспортёра; правки, внесённые только в Word, обратно в Typst не синхронизируются.

Параметры `crop-px`, `crop`, `max-height` и проверка сохранности исходников: [image-layout.md](image-layout.md).

## Проверка Word

Страницы Typst и Word могут переноситься по-разному. Успешная сборка ZIP/XML не доказывает, что титул поместился или подпись осталась рядом с изображением.

1. Запусти `preflight.py ... --docx report.docx`.
2. Открой DOCX в Word или LibreOffice, обнови все поля/содержание и сохрани. В Word обычно `Ctrl+A`, затем `F9`; проверь также колонтитулы.
3. Экспортируй его в PDF и осмотри все страницы. Для автоматической первичной отрисовки доступна команда ниже; сама конвертация **может не обновить содержание**, что необходимо проверить отдельно.
4. Если есть лимит, передай полученный PDF в `--docx-pdf` и проверь его отдельно от Typst PDF.

```bash
libreoffice --headless --convert-to pdf --outdir word-render report.docx
python3 /path/to/skill/scripts/preflight.py report.typ report.pdf --docx report.docx --docx-pdf word-render/report.pdf --max-pages 5
```

Если офисное приложение недоступно, выдай DOCX с честным указанием: структурные проверки выполнены, визуальная вёрстка Word не проверена; при включённом содержании нужно обновить поле TOC. Не называй пустое нерассчитанное содержание готовым.

Основание реализации: [python-docx: абзацы, таблицы, изображения](https://python-docx.readthedocs.io/en/latest/user/quickstart.html), [параметры абзацев](https://python-docx.readthedocs.io/en/latest/user/text.html), [Typst metadata](https://typst.app/docs/reference/introspection/metadata/).
