# Обрезка изображений кодом и ограничение размера

Скриншоты хранятся целиком. Модель задаёт видимую область; менять PNG/JPEG и сохранять обрезанные копии не требуется.

## API

```typst
#import "../settings/blocks.typ": *
#let main-part = (
  para[Параметры окна показаны на @fig-settings.],
  screenshot("images/settings.png", [Параметры окна],
    id: "fig-settings", width: 0.75,
    crop: crop-px((240, 180, 540, 320), source: (1024, 768))),
)
```

Это пример координат, а не готовая область для любого файла. `crop-px` принимает `(x, y, ширина, высота)` в пикселях исходного изображения, начало координат — левый верхний угол. `source: (W, H)` — фактические размеры исходника. Все размеры должны быть положительны; прямоугольник должен полностью помещаться в исходнике. Макрос возвращает доли обрезки `left/top/right/bottom` от полного размера изображения. `crop: none` оставляет весь кадр. Доли при прямом задании должны лежать в диапазоне от 0 включительно до 1, сумма противоположных полей — меньше 1.

Поля блока `screenshot`:

| Поле | Смысл |
| --- | --- |
| `width: 0.92` | Максимальная доля ширины текстового поля, от 0 до 1; относится к видимой области |
| `crop: none` | Область просмотра; обычно результат `crop-px(...)` |
| `max-height: none` | Предел высоты изображения в мм; `none` использует `config.figure-max-height` |

По умолчанию `figure-max-height: 80` мм. Вместе с подписью и интервалами это примерно треть A4. Подпись имеет самостоятельную высоту, поэтому длинную подпись тоже учитывай при визуальной проверке. Пропорции видимого фрагмента сохраняются, а заданная ширина может уменьшиться из-за предела высоты. Для сложной схемы, требующей большего масштаба:

```typst
screenshot("images/network.png", [Схема сети], id: "fig-network",
  width: 1, max-height: 140)
```

После уменьшения проверь читаемость полей и значений. Высокие формы с мелкими надписями могут требовать содержательной обрезки пустот или явно увеличенного лимита. Не обрезай значимый контекст и не разбивай один результат так, чтобы скрыть ошибку.

## Рендеринг

`settings/image-layout.typ` содержит `report-image(path, width, max-height, crop)`. Typst измеряет соотношение сторон исходника, рассчитывает размер видимой области и помещает сдвинутое полное изображение в `box(clip: true)`. Простое `image(..., fit: "cover")` не заменяет этот макрос: оно не задаёт выбранную область по координатам.

В DOCX экспортёр вкладывает оригинальные байты PNG/JPEG, задаёт прямоугольник обрезки `a:srcRect` и размеры фигуры с учётом пропорций видимого фрагмента. Обрезку можно изменить штатными средствами Word. Экспорт не создаёт промежуточного растра и не требует Pillow. PNG/JPEG остаются поддерживаемыми форматами Word; для других форматов действуют ограничения из [docx.md](docx.md).

## Проверка

Собери PDF и DOCX, затем отрендери Word в офисном приложении. Осмотри выбранную область в обоих форматах, подпись, пропорции и размер. При изменении механизма обрезки проверяй, что исходники и медиа внутри DOCX совпадают по байтам, что некорректные прямоугольники отклоняются, а размеры рисунка не превышают заданные пределы. Проверочные изображения должны оставаться во временном проекте.
