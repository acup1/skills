# Модульный проект и API блоков

```text
project/
├── report.typ                  сборка модулей
├── images/                     только используемые изображения
├── tables/results.typ          определения таблиц
├── titles/                     lab.typ, mai-course.typ, generic.typ, selected.typ
├── settings/                   config.typ, metadata.typ, blocks.typ, render.typ
├── chapters/                   главы, каждая отдельным .typ
└── bibliography/sources.typ    реальные источники в порядке первого упоминания
```

`init_project.py` сначала создаёт эту структуру. Файлы `.typ` импортируют друг друга относительными путями; `report.typ` располагается в корне. Пути в `screenshot()` задаются **от корня проекта**, например `images/01.png`, даже если вызов находится в `chapters/`. Не используй `../images` в данных блока.

Каждый модуль главы экспортирует массив. Один элемент в массиве требует завершающей запятой. Это данные на языке Typst, не дублирующий JSON/Markdown. Текст в `[...]` поддерживает обычную разметку Typst; `prepare()` один раз назначает номера и передаёт одну модель обоим экспортёрам.

```typst
#import "../settings/blocks.typ": *
#import "../tables/results.typ": results

#let main-part = (
  section([Практическая часть], id: "sec-practice"),
  section([Проверка], level: 2),
  para[Результат проверки приведён на @fig-check.],
  screenshot("images/01-check.png", [Результат проверки], id: "fig-check"),
  para[Наблюдавшиеся результаты сведены в @tab-results.],
  ..results,
)
```

Создавай такой блок рисунка только при наличии соответствующего реального изображения. Скрипт не создаёт фиктивных скриншотов для примера.

## Блоки

| Функция | Параметры / смысл |
| --- | --- |
| `para[Текст]` | Один абзац; для второго используй ещё один блок, а не пустую строку внутри |
| `section([Название], level: 1, id: none, numbered: true, new-page: none)` | Нумерованный заголовок уровня 1–3 с точкой после номера; разрыв по профилю |
| `structural([ВВЕДЕНИЕ], new-page: none)` | Ненумерованный заголовок по центру прописными; с новой страницы, входит в содержание |
| `screenshot("images/file.png", [Подпись], id: "fig-id", width: 0.92, crop: none, max-height: none)` | Один рисунок; максимальная ширина как доля текстового поля, `max-height` в мм; обрезка через `crop-px` |
| `result-table([Подпись], headers, rows, id: "tab-id", widths: none)` | Заголовки и строки — массивы содержимого; веса ширины столбцов — положительные числа |
| `formula($a = b/c$, id: "eq-id")` | Отдельная нумерованная формула |
| `bullet-list(([Пункт], [Пункт]))` | Маркированный список с тире |
| `numbered-list(([Шаг], [Шаг]))` | Нумерованный список с 1 |
| `source("src-id", [Описание])` | Библиографическая запись |
| `new-page()` | Явный разрыв страницы, только когда он нужен |

Используй уникальные `id` и ссылки `@id`. Префиксы `fig-`, `tab-`, `eq-`, `src-` удобны, но необязательны. Ссылки вычисляются по виду блока, поэтому таблица никогда не становится `рис. N`. Подписи всегда полные. Неразрывный пробел не позволяет отделить номер от `рис.` / `табл.`.

Определение таблицы хранится в `tables/`, а предложение со ссылкой — в соответствующей главе. Ниже **синтаксический пример**, не экспериментальные данные для отчёта:

```typst
#import "../settings/blocks.typ": result-table
#let results = (
  result-table(
    [Наблюдавшиеся результаты],
    ([Проверка], [Результат]),
    (([Название проверки из материалов], [Фактический результат]),),
    id: "tab-results",
    widths: (2, 3),
  ),
)
```

Простые прямоугольные таблицы поддерживаются обоими форматами, включая повтор заголовка на следующей странице. Объединённые ячейки и специальные подписи «Продолжение таблицы» требуют отдельного расширения и визуальной проверки; не заявляй строгого соответствия многостраничной таблицы без него.

Формулы:

```typst
section([Расчёт]),
para[Используем выражение @eq-main.],
formula($a + b = frac(c, d)$, id: "eq-main"),
para[где $a$ — первое слагаемое; $b$ — второе слагаемое.],
formula($H = mat(1, 0; 0, 1)$, id: "eq-matrix"),
```

`equation-numbering: "section"` даёт `(1.1)`, `(1.2)` и сброс только при следующей нумерованной главе уровня 1. Подразделы счётчик не сбрасывают. Для формул до первой главы используй сквозную нумерацию либо измени структуру осознанно. Не воспроизводи квадратные скобки вокруг номеров формул и сброс при каждом подзаголовке из исходного образца.

При переносе старого текста MiTeX можно оставить в отдельном проекте только для PDF, если пакет доступен и нужен. Не добавляй сетевую зависимость `@preview/mitex` всем отчётам. Для DOCX переводи формулы в поддерживаемую нативную математику Typst либо расширяй экспортёр: произвольные контекстные функции пакетов не экспортируются автоматически.

Обрезка кодом без изменения файла, ограничение высоты и исключения для схем: [image-layout.md](image-layout.md).

## Заголовки

`section` и `structural` создают настоящие заголовки; номера с завершающей точкой назначает `prepare` (`heading-number-suffix: "."`), не набирай их в тексте. Суффикс относится только к заголовкам: номера рисунков, таблиц, страниц и формул не меняются. У `section(..., numbered: false)` сохраняются стиль и уровень, но нет номера. `structural` предназначен для ненумерованных структурных элементов по центру прописными. Кегль равен `font-size`; полужирное начертание задаётся `heading-bold`, интервалы в пунктах — массивами `heading-space-before: (12, 9, 6)` и `heading-space-after: (6, 6, 3)`. Экспортёр использует те же параметры для стилей Word. Правила всех типов и различия профилей приведены в [SKILL.md](../SKILL.md#заголовки-всех-уровней).

`new-page: none` выбирает разрыв автоматически: в лабораторной обычные разделы и подразделы идут подряд; в курсовой раздел уровня 1 начинается с новой страницы, уровни 2–3 продолжаются. `structural()` начинает отдельный раздел с новой страницы; следующий раздел первого уровня тоже отделяется разрывом. `new-page: true/false` — явное исключение. Итоговый логический флаг вычисляет `prepare()`, его используют оба экспортёра. Не назначай всей Word-стилизации Heading 1 разрыв страницы: в лабораторной это нарушит правило. Слабые разрывы Typst и `page_break_before` Word не должны давать пустых страниц.

## Литература и содержание

В `bibliography/sources.typ` экспортируй `sources = (source(...), ...)`. В тексте `@src-id` становится `[N]`; номера зависят от порядка источников, который должен совпадать с первым цитированием. Пустой массив не создаёт раздел литературы. Внешние ссылки оформляй `#link("https://...")[Название]`. Названия, авторов и выходные данные сверяй с фактическим источником.

Содержание включается `contents: true`, глубина — `contents-depth`. В Typst оно обновляется при компиляции, в Word это поле TOC, требующее обновления в офисном приложении.

## Геометрия и шрифты

Числа в `config.typ`: поля/отступы в мм, кегль в пт, ширины изображений в долях страницы. `top-edge: 0.8em`, `bottom-edge: -0.2em` и `leading: 0.5em` задают шаг обычного текста 1,5 em (21 пт при 14 пт). Нижняя граница должна быть ниже базовой линии; положительные `0.2em` дают неверный шаг. Между абзацами `spacing` равен `leading` плюс `paragraph-spacing` в пт; при `paragraph-spacing: 0` межабзацный шаг совпадает с межстрочным. Не ставь `spacing: 0pt` для имитации Word «до/после 0 пт». Сам по себе `leading: 0.75em` или `0.5em` не является универсальным аналогом Word «1,5»: без заданных границ он зависит от метрик шрифта. Высокая строчная формула может увеличить интервал; проверяй такие места визуально. В DOCX установлен множитель 1,5, интервал до 0 пт и после `paragraph-spacing` пт. `hyphenate: false` отключает автоматические переносы в Typst и DOCX; в Word дополнительно задан запрет переносов в стилях.

Математический шрифт по умолчанию — Cambria Math (14 пт базового кегля, индексы масштабируются). Он указан явно и проверяется отдельно от TNR. Если его нет, выбери доступный математический шрифт и согласуй требование, когда преподаватель ограничивает шрифты формул.
